## Recommendation
1. Primary: swap U1 to STM32F405VGT6 (LCSC/JLC C56621). It is a pure BOM change. JLC stock 1,050 pcs (10x the F407's 103 today), USD 7.62 @1, 6.57 @10, 5.92 @30, 5.38 @100 (tools/lcsc.py, 2026-11-17). That is about USD 1.80 more per board than the F407 at 100 (F407 C12345: 3.58 @100). Still an extended part, so no change to the extended-part fee. VERIFIED (prices), INFERRED (pure BOM swap, see section 4).
2. Why it is safe: same die family and same datasheet DS8626 as the F407 (the repo's own datasheet covers both), same LQFP100 pin table, no feature this board uses is missing (F405 lacks Ethernet and camera only; this board uses neither). The rusEFI F4 build is chip-agnostic at the define level: board.mk sets -DSTM32F407xx and rusEFI's own F4 port also uses that define for non-F429 parts (hw_ports.mk, section 2). No firmware file needs to change.
3. Fallback: STM32F427VGT6 (C117815). JLC stock 2,585 pcs, USD 9.02 @1, 7.85 @10, 6.61 @30, 6.01 @100 (about +2.44 vs F407 at 100). LQFP100 pins identical to the F407 for every pin that matters (section 4). rusEFI ships hardware that puts an STM32F429 in an LQFP100 and runs the F4 firmware on it (Hellen mega-mcu100 / uaefi), and the F4 code reads the flash size at run time. Needs a bench test before shipping; firmware change optional (see section 2).
4. Not recommended: any F7 / H7 part. They are not pin-compatible with the F407 in LQFP100 (pins 19 onward shift), so it is a re-layout, and their stock is worse (F765VIT6 52, F767VIT6 21, F746VGT6 0, H743VIT6 44 plus 787 of the tape-and-reel code, H723VGT6 0). The pinned rusEFI checkout also lacks the H7 hardware-layer directory.
5. Honest note on "keep the F407": the F407 stock at JLC is volatile (72 on 11-16, 103 on 11-17), so it can serve small lots, but one 100-board lot would empty it. If the owner wants to keep exactly the F407, JLC global sourcing is the route (section 5): 9-20 business days, no stated minimum, extra per-part fee is small (max USD 0.078 per component), but price and supplier are not shown until you search the part in the Parts Manager (not checked: needs an account). Franchised stock is much dearer: TME USD 9.97 @1 / 8.69 @90 (1,162 pcs).
6. Hardware change list for the primary (corrected by fact-check): no copper or footprint change, but the part number is written in several generated files, so edit the source and regenerate: repo/scripts/design.py:169 (add('U1', 'STM32F407VGT6', 'LQFP100', 'C12345', ...)), repo/scripts/mpn.json, repo/daughterboard/mcu.kicad_sch and miata_ecu_daughter.kicad_pcb (value/LCSC fields), daughterboard/fab/*_jlcpcb_bom.csv, viewer/parts.json and viewer/index.html. Also check the silk/value text "STM32F407". Firmware: none required; optional comment edits in repo/firmware/board/board.mk line 1, README.md line 4, tools/check_image.py line 7 (text only).
7. Risks: (a) F405 availability was exactly 1,050 on both 11-15/16 and today, i.e. the number looks static, so check before ordering; (b) device ID: F405/407 = 0x413 and F42x/43x = 0x419 (VERIFIED, comment in hw_layer/ports/stm32/stm32_common.cpp:278-282; option-bytes-f427.json deviceId 1049). rusEFI already branches at run time on isStm32F42x() (stm32_adc_v2.cpp:151, stm32_opt.cpp:42/115, lua_heap.cpp:119), so the F427 path is exercised by the shared code, but any DFU/option-bytes tool needs the F427 JSON; (c) no one has ever powered this board, so none of this is bench-proven.
8. The wideband MCU STM32F103C8T6 (C8734): JLC stock 215,410, LCSC 21,640, USD 1.46 @1 / 1.01 @250 / 0.93 @1000, "EXTENDED (PREFERRED)". No action.

- Outputs (plain GPIO, through 74LVC4245 level shifter, enabled by PA8 DRV_EN open-drain): PB8/PB9/PE0/PE1 IGN4..1; PB4-PB7 INJ4..1; PB3 IACV; PD5-PD7 ALT/BOOST/VVT; PE2-PE6, PC13, PC14 low-side outputs (LS7, TACH, CEL, FAN, AC, MAINRLY, FP).

## 2. What rusEFI builds for, and what a board must change
All VERIFIED from the pinned tree repo/firmware/ext/rusefi/firmware unless marked.
- config/boards/readme.md:5-8: "most supported platforms are stm32f4 and stm32f7; alpha version support stm32h7"; kinetis, cypress, AT32 "experimental/abandoned". hw_layer/ports/stm32/stm32f4/readme.md: "As of 2025 we barely fit into stm32f4 RAM, proper designs should really use at least stm32f7".
- PROJECT_CPU values used by shipped boards: ARCH_STM32F4 (26 env files), ARCH_STM32F7 (16), ARCH_STM32H7 (1: atlas board.mk). hw_layer/ports/stm32/ contains only stm32f4/ and stm32f7/ directories, yet rusefi.mk:50-58 names ports/stm32/stm32h7: the H7 hardware layer is missing from this checkout, so an H7 build cannot be done from the pinned tree (INFERRED that the pin is simply old or pruned; not investigated).
- F4 port (stm32f4/hw_ports.mk): IS_STM32F429=yes gives -DSTM32F429xx -DSTM32F429_MCUCONF -DEFI_IS_F42x and linker symbol STM32F4_HAS_SRAM3=1 (extra 64 kB RAM region, STM32F4.ld lines 12-14, 40); IS_AT32F435=yes selects Artery; anything else gives -DSTM32F407xx. Boards that set IS_STM32F429: proteus (F4 variant, LQFP176), nucleo_f429, f429-208, f429-discovery. Clock: stm32f4/cfg/mcuconf.h:59-62 PLLN 336, PLLP 2 (168 MHz), PLLM follows the HSE auto-detection (osc_detector.cpp: sets PLLM to N for an N MHz crystal); mcuconf_common_f4_f7.h:441 default ENABLE_AUTO_DETECT_HSE. F7: PLLN 432 (216 MHz), same auto-detect.
- Flash layout: stm32f4/mpu_util.cpp:31-70 selects the settings sector at run time from the flash-size register (512 kB, 1 MB -> 0x080E0000 first copy, 0x080C0000 second; 2 MB -> 0x081E0000 / 0x081C0000, or the 1.5 MB layout when EFI_FLASH_USE_1500_OF_2MB). STM32F4.ld: default image 768k, 32k OpenBLT bootloader, OpenBLT shared area 16 bytes. So one F4 image runs on 1 MB parts of either family.
- Which MCU the Hellen modules use (ext/hellen-one/modules/*/BOM): mega-mcu100 (LQFP100): STM32F429VGT6 C95448 (v0.1, 0.2) and STM32F429VIT6 C92002 (v0.3); uaefi v0.2 uses STM32F429VIT6 LQFP100; mcu (176): STM32F427IGT6; mcu144 / mega-mcu144: STM32F767ZI; mega-mcu64: STM32F405RGT6 LQFP64; wideband module STM32F042K6. rusEFI's uaefi board (config/boards/hellen/uaefi/board.mk + meta-info.env: PROJECT_CPU=ARCH_STM32F4, USE_OPENBLT=yes, OPENBLT_WIPE_FLASH_END_EXCLUSIVE=0x08100000, i.e. 1 MB) does not set IS_STM32F429, so the shipped uaefi F4 firmware is built with -DSTM32F407xx and runs on the F429 LQFP100 hardware. INFERRED link between the BOM and the build (the build file does not name the chip); the pieces are VERIFIED.
- Known issues: rusEFI issue #8396 (R10): ChibiOS-22 era F407 image hard-faults on APM32 clones; not relevant to ST parts. ES0182 errata for F40x/F42x were not read (st.com unreachable in R10; not retried).
- What changes per target:
  - F405VGT6: nothing (chip define, linker, flash size, clock tree, bootloader, option bytes all the same as F407). Option-bytes JSON for F407 (deviceId 1043 = 0x413) is the same file; the F405 ID is UNVERIFIED (believed 0x413).
  - F427VGT6: minimum nothing (as uaefi does); recommended: in board.mk set `IS_STM32F429 = yes` (before the include of the F4 hw_ports.mk, as proteus/board.mk:4-6 does) to get the F42x defines and the extra SRAM3, then check the build (not run here); use option-bytes-f427.json (deviceId 1049 = 0x419) where tools read it; OpenBLT builds from the same meta-info.env. Whether OpenBLT in this repo's bootloader copes with the F42x flash sector map was not checked (openblt_flash.cpp has no sector table in the pinned tree; INFERRED it uses rusEFI's flashSectorSize()). Not tested.
  - Files in this repo that name the chip (text only, no behaviour): repo/firmware/board/board.mk:1,7, firmware/README.md:4, firmware/tools/check_image.py:7, board_checks.py (F407 pin table; for F427 the pin names are the same, so it still passes), circuit_sim.py:46, tools/board_thermal.py:56 (thermal model entry 'STM32F407VGT6'; the F405 has the same package and theta-JA).

## 4. Pin compatibility with the existing LQFP100 footprint
Method: pdftotext of each datasheet's pin-definition table, LQFP100 column parsed per pin (work/followup/Q2-better-stocked-mcu/parse.py), compared with repo/scripts/stm32f407v_lqfp100_pins.txt (which P01 showed agrees with the ST XML), then the few unparsed pins read by hand.
- F405VGT6: same datasheet and pin table as F407 (DS8626 Rev 9 in datasheets/C12345_STM32F407VGT6.pdf, covers STM32F405xx/407xx). Zero differing pins. VERIFIED (P01 summary 8; DS8626 title lines).
- F427VGT6 (DS STM32F427xx/F429xx DocID024030 Rev 4, table 10 "pin and ball definitions", p.51 onward): every LQFP100 pin has the same function as the F407 for all 100 pins; only naming differs (pin 8/9 shown as OSC32_IN/OUT, pin 12/13 as PH0-OSC_IN / OSC_OUT). Hand-checked rows: pin 6 VBAT, 14 NRST, 20 VSSA, 21 VREF+, 22 VDDA, 27 VSS, 49 VCAP_1, 73 VCAP_2, 94 BOOT0, 99 VSS, 100 VDD (lines 3775, 4091 of the text). The power-relevant items: VCAP1/VCAP2 are still 2.2 uF, ESR < 2 ohm (table 19), so C9/C10 stay; PDR_ON and BYPASS_REG do not exist on LQFP100 ("all packages except LQFP100 can disable internal reset with PDR_ON", text line 1289; BYPASS_REG listed for larger packages only, line 1339/1519), so there is no new pin to tie. PA4 and PA5 remain TTa (ADC IN4/IN5 + DAC), same as F407 (text line 3573); other analog pins FT. Used alternate functions found on the same pins in the F427 AF table: CAN2_RX/TX on PB12/PB13, OTG_FS DM/DP on PA11/PA12, USART3 TX/RX on PD8/PD9, SPI2 on PB10/PB14/PB15, USART6 on PC6/PC7, TIM3_CH1 on PB4 (checked by text search, which is fuzzy for split table rows; ADC channel numbers on PA1..PA7, PC4/5, PB0/1 were not individually confirmed in the F427 table because the text split them, INFERRED same as F407; PA4 confirmed as IN4). Differences that matter for operation, not pinout: max 180 MHz (rusEFI runs it at 168 MHz via PLLN 336/P2, no over-drive), IDD at 168 MHz not compared with F407's 102 mA max (thermal margin of the board is already thin per P01; check Table 24 of the F427 datasheet before a hot-case claim: NOT CHECKED). Verdict: pure BOM change on the PCB; small firmware/bench validation.
- F469VIT6: LQFP100 pin 2 is VSS, 3 VBAT, pin 43 VCAP1, 55/56/59/62/65 are DSI supplies (VDDDSI, VCAPDSI, VSSDSI, VDD12DSI, VDDUSB) and the remaining pins are shifted: re-layout. INFERRED from the parsed table (parser output was shifted but internally consistent; not hand-verified). Not pursued.
- F765VIT6 / H743VIT6 (F746, F767, H723 share the F7/H7 LQFP100 layout; F746/H723 datasheets not downloaded: UNVERIFIED for those two): LQFP100 pins 1-18 match the F407 names, but from pin 19 the sequence is VSSA(19) VREF+(20) VDDA(21) PA0(22) PA1(23) PA2(24) PA3(25) VSS(26) VDD(27) PA4(28)...; so VDD/VSS/analog supply pins and all analog inputs move by one or more pins. Also pin 48 is VCAP_1/VCAP at a different position than 49 and the H7 supply scheme differs. Re-layout (U1 region of the 6-layer board, fan-out and decoupling), not a BOM change. VERIFIED table shifts from parse; the full H7 supply/VCAP scheme not read.
- Summary: F405 = pure BOM change; F427 = pure BOM change on the PCB (no layout), plus bench validation; F4x9/F437 same as F427; F469, F7, H7 = re-layout.

## 5. Purchasing alternative: JLCPCB pre-order and global sourcing (help pages read today)
- Pre-order parts (https://jlcpcb.com/help/article/62-pre-ordering-parts-terms-conditions): if lead time after confirming with the supplier is within 18 days JLC buys directly; otherwise it emails to confirm; cannot cancel once the quotation is finished; unusable surplus stored free (0.03% of the minimum package per year loss); pre-ordered parts cannot be mixed with global-sourcing or consigned stock of the same part number in one assembly order; shortfall of less than 3 pcs is refunded not replenished; no MOQ figure is given on the page. VERIFIED.
- Global sourcing (https://jlcpcb.com/help/article/63-global-sourcing-parts-order-terms-conditions and .../60-How-to-use-JLCPCB-Global-Sourcing-Parts-Service): "Normally it's 9-20 business days"; no MOQ stated beyond the assembly minimum and attrition quantity; fee per separate component USD 0.017 per pin up to 5 pins, "maximum $0.078 per component" above 5 pins (so max USD 0.078 for an LQFP100, applies to parts not on tape/reel); USD 20 commodity inspection fee per kind of part applies to switches, fuses, connectors, batteries (not stated for ICs); customs duty 3-30% on some part types; cannot be cancelled or returned once paid; batches may differ; no shipping charge. Search by manufacturer part number in Parts Manager > Order Parts > Global Sourcing Parts, pick a supplier. If the part is in JLC's library JLC recommends buying from JLC. VERIFIED (via page fetch summaries of the pages, secondary reading by a small model; the two pages differ slightly on the per-pin cap, the search-result snippet said 0.17 for more than 10 pins and the fetch said 0.078, so re-fetched during fact-check: article 63 states max USD 0.078 for parts over 5 pins and does NOT state lead time or MOQ; the 9-20 business days comes from article 60; the USD 20 inspection fee is worded "for each kind of part" on article 63 and may apply to ICs too, so budget USD 20 per lot).
