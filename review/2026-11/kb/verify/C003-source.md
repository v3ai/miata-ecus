# C003 primary-source verification: PARTLY (medium severity, ordered boards affected but largely documented)

Checked:
- ord_mb8993 / ord_mb9495 pcb_nets: IN_SW2 (A/C, J1.1Q) = JD2.16 + R21.2, IN_SW3 (clutch, J1.1V) = JD2.17 + R22.2; R21/R22 = 4.7k to VBAT_IN. They are "not fitted" pull-up options (ordered-boards 1989-93 & 1994-95 README: "Switch inputs (R20-R22, not fitted)"; VERIFICATION.md M4 "Fit per car"). So "no pull-up" is by design and already documented. Daughterboard (ord_db) has 22k/10k divider (R67/R68, R69/R70) to GND, no pull-up. TRUE.
- Firmware miata_board.cpp setInputs(): sets acSwitch=MIATA_SW2 and clutchDownPin=MIATA_SW3, no acSwitchMode / clutchDownPinMode (grep for PI_ in repo/firmware/board and ordered firmware: none). TRUE for A/C.
- rusEFI default (engine_configuration.cpp:223) clutchDownPinMode = PI_PULLUP (inverted, active-low) - so the clutch polarity IS already active-low by default; the claim "preset sets no pin mode so clutch wrong" is WRONG for the clutch. Hellen NB2 uses PI_INVERTED_DEFAULT (same active-low semantics). rusEFI's own mazda_miata_1_6 NA preset also uses clutchDownPinMode=PI_PULLUP and leaves acSwitchMode default.
- acSwitchMode default is 0 (active-high). debounce.cpp:109-115 inverts only for PI_PULLUP. R16 (kb/research): 1Q "A/C switch below 2.5 V on", 1V "0 V neutral or clutch in / 12 V in gear" (FSM measurements with stock ECU attached; the stock ECU likely supplies the pull-up, so open-collector vs driven is not established). So with R21 fitted and A/C mode unchanged, A/C reads "requested" when off (12 V) and not when on: inverted. TRUE for A/C on 1989-95 if R16 holds.
- Clutch with R22 unfitted: pin is floating, MCU internal pull-up (PI_PULLUP, ~40k) against 10k to GND gives about 0.7 V = low = clutch "pressed" permanently (not "0 V = inactive" as claimed). I did not measure this; derived from divider net.
- 1996-2005 boards (NB, cur_mb9900/0105): 4F/4I/1P cites cannot be verified here; out of the title's scope.

Corrected statement: On the ordered 1989-93/1994-95 boards the A/C input (1Q) polarity is not set in firmware: acSwitchMode stays at default active-high while R16 says the stock signal is active-low, so with R21 fitted the A/C request is inverted, and with R21 unfitted A/C is never requested if 1Q is open collector. The clutch input default (PI_PULLUP, active-low) is already correct once R22 is fitted; unfitted it reads permanently "clutch down". The unfitted pull-ups themselves are documented.
Fix: firmware-only for polarity (acSwitchMode = PI_PULLUP / PI_INVERTED_DEFAULT in the 1989-95 presets); R21/R22 hand-fitting only if the car signal is ground-switched (measure 1Q/1V with ECU unplugged first). No board respin needed.
